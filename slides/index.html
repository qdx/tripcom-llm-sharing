Timeline

From GPT-2 to Harness Engineering
7 years in 10 minutes

Era 1 · Prompt Engineering · 2019–2022

Learning to talk to models. Humans craft input; model generates output.

Feb 2019 — GPT-2 (1.5B) released. "Too dangerous to release." Scaling era begins.
May 2020 — GPT-3 (175B). Few-shot prompting works. "Prompt engineering" is born.
Jan 2022 — Chain-of-Thought paper. "Let's think step by step" changes everything.
Mar 2022 — InstructGPT / RLHF. Models that follow instructions.
Nov 2022 — ChatGPT launches. 100M users in 2 months. The "iPhone moment."

"For the first time, you could get a model to do tasks without fine-tuning — just by writing better prompts."

Era 2 · Context Engineering · 2023–2024

Giving models superpowers. RAG, tools, plugins, agents.

Mar 2023 — GPT-4 released. Tool use becomes viable.
Mar 2023 — ChatGPT Plugins + AutoGPT. Agent era begins.
Jun 2023 — OpenAI Function Calling. Standardized tool use.
Nov 2023 — GPT-4 Turbo: 128K context window (16× increase).
Early 2024 — RAG goes mainstream. Vector DBs everywhere.
2024 — Dify, Coze: no-code AI platforms.

"+1 for 'context engineering' over 'prompt engineering'. Context engineering is the delicate art and science of filling the context window with just the right information for the next step."

— Andrej Karpathy, June 2025

Key insight: The prompt is a small part. What matters is everything in the context window — retrieved docs, tool outputs, history, system instructions.

Era 3 · Harness Engineering · 2025–2026

Engineering the environment, not the prompt. Models reason; humans build the world.

Sep 2024 — OpenAI o1: reasoning models internalize CoT.
Oct 2024 — Claude Computer Use. Models operate full desktops.
Nov 2024 — Anthropic MCP. "USB-C for AI."
Jan 2025 — DeepSeek-R1. Open-source reasoning.
Feb 2025 — Claude Code. Terminal as harness.
Feb 5, 2026 — Mitchell Hashimoto coins "Harness Engineering."
Feb 11, 2026 — OpenAI adopts the term. 0 hand-written code, 1M lines.

"Anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again."

— Mitchell Hashimoto, Feb 2026

The shift: From "telling the model what to think" → "building the world the model operates in."

Demo 2: ReAct Agent

Context Engineering Era

A travel planning agent with real tools
Thought → Action → Observation loops

ReAct Pattern: Think → Act → Observe

Scenario: "Plan a 3-day Tokyo trip from Shanghai. Budget ¥15,000/day."

system You are a travel planning agent with access to: search_flights, search_hotels, search_restaurants...
user Plan a 3-day Tokyo trip. Budget ¥15,000/day.
💭 thought Let me search flights first...
tool_call search_flights(origin="PVG", dest="NRT")
tool response Found: MU523 ¥2,890 / CA921 ¥3,200 / ...
💭 thought MU523 looks good. Now hotels near Shinjuku...
... Round 2, 3, 4...
Context growing with each tool call ~4,200 / 128K

Key observations:

  • Each tool round-trip adds tokens to context
  • The model "remembers" by re-reading everything
  • After 3-4 rounds, context = mostly tool responses
  • Observation data often 10× larger than thoughts
  • ⚠️ Long agent loops can fill the context window

Demo 3: Full Agent Harness

Harness Engineering Era

A real production agent's context window
revealed in all its complexity

What a Production Harness Injects

Before the user even speaks, the context window is already rich

system — core instructions You are Claude Code, Anthropic's CLI agent...
system — AGENTS.md Read SOUL.md, USER.md, memory/active.md...
system — SOUL.md (identity) Be genuinely helpful. Have opinions. Be resourceful...
system — USER.md DChar, GMT+8, CTO @ VationX...
system — 40+ skill definitions github, slack, weather, browser, email...
system — tool schemas read(), write(), exec(), web_search()...
system — memory/active.md Current tasks, project status, daily log...
user "Hey, check the weather in Tokyo"
Before user speaks ~18,000 / 200K

The "iceberg" effect:

  • User sees: "check the weather" (6 tokens)
  • Model sees: 18,000 tokens of context
  • System prompt alone = ~15,000 tokens
  • Identity, memory, skills, tools, rules...

This is harness engineering.
The harness fills 90% of the context window before the user speaks.

Real Example: OpenAI's Codex Harness

0

lines of hand-written code

1,000,000+

lines generated by agents

1,500

PRs merged · 3 engineers · 5 months

How?

  • AGENTS.md as table of contents (~100 lines) — not a 1,000-page manual
  • Linter error messages = teaching — violations include fix instructions
  • Architecture enforced mechanically — not by humans reviewing PRs
  • "What Codex can't see doesn't exist" — all knowledge in the repo
  • Doc gardening agents — background agents fight entropy

"Give Codex a map, not a 1,000-page instruction manual."

Key Takeaways

For Trip.com engineers

Five Things to Take Away

1

The context window is the fundamental abstraction.
Every LLM interaction = filling a memory buffer. Understanding this explains everything — from prompt engineering to RAG to agent harnesses.

2

Tools make agents useful. Guardrails make agents reliable.
Function calling and RAG were table-stakes in 2024. The hard part is building the environment where agents don't break things.

3

Harness engineering is the new "DevOps for AI."
AGENTS.md, linters, progressive disclosure, doc gardening — these are infrastructure patterns, not prompt tricks.

4

The human role elevated, not diminished.
From prompt-crafting (2023) to context-orchestrating (2024) to harness-engineering (2026). Each step requires more engineering skill, not less.

5

Start building harnesses now — at Trip.com scale, it matters.
Travel domain = perfect testbed: structured data, real tools, multi-step workflows. Your booking APIs are ready-made agent tools.
